Contratos de eventos SmartPark

Versão 1. Produtor: serviço Reservas. Transporte: Azure Storage Queue smartpark-events, JSON codificado em Base64. Consumidor: Azure Function onParkingEvent.

EventoQuando ocorre
ReservaCriadaNa criação transacional da reserva.
PagamentoConfirmadoNa primeira aprovação do pagamento simulado.
ReservaCanceladaNa primeira transição para cancelada.

Garantias e falhas

Reserva e Outbox são persistidas na mesma transação SQL. O Timer solicita despacho a cada dois minutos. A publicação é pelo menos uma vez; o consumidor deduplica por eventId no Table Storage (PartitionKey=userId e RowKey=eventId). Não há garantia de ordenação global. Após cinco falhas, a mensagem vai para smartpark-events-poison. Eventos inválidos são rejeitados; não são descartados silenciosamente.

Os eventos não são endpoints HTTP de comando. A consulta HTTP de notificações é protegida por credencial interna e acessada pelo BFF em nome do usuário autenticado.
